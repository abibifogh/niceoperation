# niceoperation.com

The public site for the NiceOps suite. One file, `site/index.html`, with the
styles inside it. No build step, nothing to install, nothing to compile. Open
it in a browser to see it exactly as it will look live.

## How the page is laid out

The old site was a flat register: a masthead, a paragraph, six links, four
principles, an email address. Everything sat at the same level, so a visitor
could see *that* there were six tools but not what the thing as a whole was,
which one to care about first, or whether any of it was usable yet.

This one is arranged as a suite with a spine:

| Section | `id` | What it is for |
| --- | --- | --- |
| Notice bar | — | The first thing on the page says the suite is not open yet |
| Hero | — | What the thing is, plus a diagram putting Insight above the systems |
| The problem | `#problem` | Four questions no single system in a hotel can answer |
| The suite | `#suite` | Eight cards, Insight first and full-width, each with a status badge |
| Insight | `#insight` | The hub on its own: one sign-in, and the cross-system findings |
| How it works | `#how` | Three steps — the floor records, each system derives, Insight compares |
| Approach | `#approach` | The four principles, carried over unchanged |
| Status | `#status` | A table of every system and where it stands |
| Questions | `#faq` | Six, including the two that are easy to dodge |
| Contact | `#contact` | One email address |
| Footer | — | Four columns |

The order is deliberate: nobody is asked to care about a tool before they have
been shown the problem it belongs to, and nobody reaches a tool card without
having already read that none of them are open.

## Marking a tool live

Every tool carries a status in exactly one place — the `data-status` attribute
on its `<article class="entry">` in the suite grid, and on its `<tr>` in the
status table. Three values are styled:

| Value | Badge reads | Colour |
| --- | --- | --- |
| `building` | In development | brass |
| `soon` | Coming soon | sage |
| `live` | Live | sage |

Everything is `building` today. To change one, edit its `data-status` **and**
the text inside its `<span class="badge">` — the text is in the markup rather
than generated by CSS so that screen readers announce it.

When a tool really does open, that is also the moment to give its card an
address to go to. The cards are `<article>` elements, not links, because there
is nothing yet to link to; turn the one that has opened into an `<a href="…">`
and it will pick up the existing hover treatment as it is.

Once every tool is live, delete the `.notice` bar at the top of `<body>`, the
`hero-foot` line under the hero buttons, the "Nothing here is open yet"
heading in `#status`, and the first entry in `#faq`.

## The other things most likely to need changing

| What | Where to look for it |
| --- | --- |
| The contact address | `mailto:hello@niceoperation.com`, three times |
| A tool's description | Inside that tool's `<article class="entry">` |
| A tool's address | The `<div class="entry-code">` on that card, and its row in `#status` |
| Adding another tool | Copy a whole `<article class="entry">…</article>` block, edit it, add a row to the status table and a footer link, and change "Eight systems" in the heading above the grid |
| Colours | The `:root` token block at the top of the `<style>`, which has light and dark sets |

## Publishing

Hosted by Cloudflare, connected to this repository:

- Project name: `niceops-site`
- Build command: *(leave empty)*
- Deploy command: `npx wrangler deploy`
- Custom domains: `niceoperation.com` and `www.niceoperation.com`

`wrangler.jsonc` says the site is the files in `site/` and nothing else, which
is why there is no "build output directory" to fill in — the file already
answers that question. If Cloudflare offers the older **Pages** flow instead
(Workers & Pages → Create → Pages → Connect to Git), it works just as well:
leave the build command empty and set the build output directory to `site`.

> The site used to be published from `website/` inside the `snpos` repository.
> It lives here now. When this repository is connected, disconnect the old
> `niceops-site` project pointed at `snpos`, or the two will fight over the
> custom domain.

## What is deliberately not here

No analytics, no cookie banner, no fonts fetched from anywhere else, no
tracking, no JavaScript at all. The page loads from one request and works on a
bad connection, which is the same standard the tools it describes are held to.
The content security policy in `site/_headers` is written tightly enough to
prove it.

There are also no claims that cannot be backed up: no customer counts, no
testimonials, no logos, no pricing. Add those when they are real.
